## Context

QA of wave 8G found, on 2026-10-10, that a design returned to by Back or Forward is shown from the router's kept copy of its page: older than the stored design, and as saved. The next edit is sent at the older revision and answered `409`; *overwrite* then drops the earlier edit (backlog 168, C2-1). A reviewer found the same path for a failure's backoff (GL-R4.1), and ADR 0156 recorded a third case as a limit: a write sent and not yet answered when its design is loaded again. It is older than 8G, and not Q35's family (an older page, not an older cookie). It violated ADR 0002 decisions 15 and 16 (*"leave the database holding a state the customer did not end at"*; *"the state cannot silently diverge from what is stored"*) [doc, as quoted by the plan's point 2]. It was classed an **implementation defect**; the review's case a **contract gap** (ADR 0148 E3 rules one design only).

## Decisions

### 1. The rule (K2.1, ruled again on 2026-10-12)

*A design's editor never offers an edit on a copy older than the one stored, and never shows as saved a design for which this tab still holds a write.* It has two halves with two sources: what the server holds arrives with the write-access probe's answer (decision 2); what the tab holds is the writer's to say (decision 3).

The architect's wording of 2026-10-10, *"a design's page shown again by Back or Forward never shows a copy older than the one stored"*, is **replaced** in three ways: *shows* becomes *offers an edit on* (between the page and the answer the older copy is on the screen, locked: L1, Q41); *a design's page* becomes *a design's editor* (the review is decision 4); *by Back or Forward* is dropped (the rule is on the load, not on how the customer arrived).

### 2. The probe's answer is taken whole, in one store write (K2.2, with A2)

When the probe answers for the design the store holds: **if the store holds no unsaved edit (`design === savedDesign`) and the answer's revision is the greater (`isGreaterRevision`), the store takes the answer's design and revision with its `canWrite`, all at once**; in every other case write access alone is applied, as before. A revision never enters the store without its document (WEB-003's intent, kept). The revision order lives in `store/revision-order.ts` and is still exported from `hydrate-and-review.tsx`, because a `qa-*` test pins it there (backlog 185).

**Amendment A2, ruled after QA's L3 (same day):** the taken copy keeps a selected body that it still holds, and its panel stays; an empty space or a body the copy lacks is cleared; a load (`hydrate`) still clears every selection. K2.2's first wording was *selection cleared, as a load does*. L3 was reached on the built server [QA-run, relayed] and is closed by A2.

*Not taken:* the tab remembering each design's last confirmed copy and asking nothing (it knows only this tab's writes and is a third copy to keep true); `router.refresh()` on a return (a second page read and render, and the editor cannot tell a return from a first arrival); the save clearing the kept page (not open to a Route Handler, `revalidatePath` and the others [doc, the plan's point 1]); the editor's guard taking the review's rule (it stays one comparison by id, ADR 0133 d4).

### 3. A design loaded again is handed the write this tab holds for it, in any state (K2.3, with items 6, A1 and A3)

The coalescer hands a load the write it holds for that design in **every state a queue can hold one**: waiting for the limit (with its time); backing off after a failure; sent and not yet answered; **ready and not yet sent** (behind the one-second interval, or behind another design's request). The screen shows that write's design, `hasBeenEdited` true, at the revision the write is conditional on; the write stays the one write on the one timer and goes no sooner; an edit made after the return joins it; **its outcome is reported to the generation that shows its design when it is answered**, not to the one that sent it. A read-only load is handed none. This extends ADR 0156 decision 10 from the write that waits to every write the tab holds.

**The hand-over's shape, as built and as ruled** [src, read by the scribe at `7d282603`: `save-coalescer.ts:123-130`, `:176`, `:290-300`]. The state is told by **two fields and a memory**: `resumesAtMs` (the limit's time, `null` for a backoff and for the two writes with no wait); an optional `heldAs: "ready" | "sent"`; and the queue's own `failureTold`, which remembers the failure last said for the write it holds and is forgotten where the queue next says `saving`. **`heldAs` is absent for a limit's wait and for a backoff; a ready write that was last said failed is handed over as that failure is, so `"ready"` means *never said failed*** (A1). The store shows a ready write unsaved and `idle` with no time. The plan's own wording asked for one field of four values; the developer built two because one would have moved `save-coalescer.return.test.ts:110-114` and `:194-198`, which the slice's *stops if* forbade, and the architect **accepted the deviation: the stop above the wording is the right order**. Whether one discriminated value is the cleaner shape is the clean-code reviewer's named question; it was left open (backlog 183).

**A3, the one lifted must-not.** A1 had forbidden touching `adoptNewerGeneration`. QA's round 2 showed a write from a newer generation replacing a backoff's write was handed to the next load as failed, because the branch dropped the backoff and left A1's memory behind [QA-run, relayed; `qa-8k2-failure-told.adversarial.test.ts:84`]. **The must-not was lifted for that one statement and for nothing else in the function**: where the branch drops a backoff's wait it forgets the failure told with it; where the limit's wait stands it is kept, since that wait is said again to the new generation in the same call. What the must-not protected stands: the branch's effect on the queue's generation, count, ticket, wait and revision is as it was (K2.4). Classed an implementation defect of A1 caused by the plan, **not out of scope**: a memory that outlives its write is wrong in the module whoever calls it.

**The branch stays (K2.4).** `scheduleSave`'s branch for a newer generation of the same design is not changed. With a throw planted in `adoptNewerGeneration`, only seven tests that drive the coalescer directly reached it; nothing in the application reaches it with a write held [developer-run, relayed]. It is a backlog entry in ADR 0123's form, not a deletion (backlog 188).

*Not taken:* handing over only the backoff (GL-R4.1's smallest fix: it leaves the write in flight, the one case where an edit is written over with no conflict said); asking the server again when a write in flight lands; telling the customer and dropping the edit (refused already in ADR 0156 d10); recording the ready write as a limit (L7; not needed once item 6 shipped with no existing test moving).

### 4. The review is not bound by decision 1 (K2.6)

A review returned to from a second design may show its kept page, older than stored; it asks nothing (ADR 0148 E3 and its rejected alternative). **Item (2) of the 2026-10-10 ruling, *"the same for the page's three steps"*, is withdrawn.** What keeps a stale offer out is 8K's refusal of a request whose revision is not the stored one (`CONTACT_DESIGN_NOT_CURRENT`, ADR 0157). The review gains K2.3 (it loads through the same `hydrate`) and its links to the editor end on the answer's copy. 8L gains criterion 14. *Reopened if* 8L cannot hold that criterion, or a customer reports a review that was not their kitchen. Dated notes: ADR 0148 Amendment D; ADR 0156, decision 10.

An arrival is honoured at the first answer about write access, or not at all (a sentence for ADR 0148 E2, found by QA's round 2: after the read limit's `429` no `?settings=open` sheet opens, and none after the retry answers; that is 8D's rule, as built and right, and the assertion stands).

### 5. Boundaries

One tab, two designs, one document; Q35 is two tabs (K2.7). The wave changed no cookie, lock, `Set-Cookie`, route, header, limiter, message leaf, or file under `app/api`, `lib/server`, `packages/` or `proxy.ts`. One effect crosses the line: the answer is the stored copy whoever wrote it, so a tab holding no unsaved edit that returns to a design also takes another tab's saved work; two tabs each holding an unsaved edit are `409`, then reload or overwrite, as before. **Backlog 169 and 171 were taken first, in a slice that changed no behaviour (K2.5)**, because S3 met both triggers.
